# AI Guru V51.8.20 — Five-Part Lazy Study-Material Generation

## Goal

Reduce study-material API usage by making the student's current study scope explicit before any material generation.

## New flow

`Textbook -> Part 1..5 -> optional Chapter -> one or more Material Types -> Create selected`

The five parts are calculated locally from the already-indexed textbook page/chapter map. Selecting a part does not call Gemini, Agnes, Sarvam, or another LLM.

## Generation boundary

For a selected part, Material Studio constructs a virtual chapter scope containing only the source IDs whose physical pages belong to that part. `generateMaterial()` receives that virtual scope instead of the full book.

If the student selects a chapter, the source IDs are intersected with the selected part before generation. Therefore a generation request cannot accidentally include the other four parts.

## Cost-control behavior

- No material is generated merely by selecting a part, chapter, or material type.
- The user must press **Create selected**.
- The previous **Create all** button was removed from Material Studio.
- Existing multi-select remains: the user may create only the material types needed for the current study session.
- Already-created material is saved and is not regenerated unless the user explicitly requests a new generation/retry.

## Example

A 200-page textbook can be presented as approximately:

- Part 1 — pp. 1–40
- Part 2 — pp. 41–80
- Part 3 — pp. 81–120
- Part 4 — pp. 121–160
- Part 5 — pp. 161–200

The actual boundaries prefer indexed chapter boundaries when the textbook has at least five chapters. For small books, local page/source partitioning keeps five parts available.

Selecting `Part 3 -> Chapter 6 -> Whiteboard Notes` sends only the source units belonging to Chapter 6 inside Part 3 to the material-generation pipeline.
